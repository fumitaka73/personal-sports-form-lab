# Personal Sports Form Lab

自分のバスケットボールのシュートを、コーチが評価した自分の **Good Form** と比較する個人用Webアプリです。動画・姿勢データ・分析履歴はブラウザのIndexedDBに保存します。動画の外部送信、有料API、ログインはありません。

## Live Pose v0.25 (Beta) — アプリ版0.9

Good Form・Single Shot・Session・履歴・動画メモを維持し、独立した **Live Pose (Beta)** タブを追加しています。Live Poseは採点、Good Form比較、音声、ボール、成否、コーチングを行いません。カメラ映像を録画・保存・アップロードせず、この端末だけで処理します。姿勢と信号の直近10秒はデバッグ用にメモリ内で保持し、IndexedDBには書きません。Sessionの検出精度改善・主要な作り直しは今回の対象外です。

### iPhone Safariで試す

1. HTTPSの公開アプリをSafariで開き、**Live Pose (Beta)** を選びます。初回は同じサイトからMediaPipeのモデルとWASMを読み込みます。
2. iPhoneを三脚に置き、**Start Camera** を押してカメラを許可します。背面カメラを優先し、音声は取得しません。背面は非鏡像、前面は鏡像で映像と骨格を一致させます。利用可能なカメラによっては希望の方向が選べないことがあります。
3. **前面 / 背面を切り替え** で切り替えます。縦・横向きにして骨格が追従することを確認してください。薄い検出は点線と橙色の点で表示します。全身が見えない場合は案内と未計測の — を表示し、助言は生成しません。
4. **基本計測を表示** はオフにできます。肘・膝角度、体幹の2D傾斜は十分に見える関節だけ計算します。高い確度は精度保証ではありません。
5. **Diagnostics** を開き、Camera FPS、Pose inference FPS、平均推論時間、動画・入力解像度、モデル名を確認します。目標FPSを15・20・30から選べます。初期値は20です。
6. 終了時は **Stop Camera**。ページ移動、バックグラウンド化、ページを閉じた場合も、メディアトラックと推論ループを停止します。Safariが権限を拒否した場合はサイト設定のカメラ許可を見直してください。

### 性能とSafariの限界

目標は15〜30推論/秒で、端末のGPU・発熱・低電力モード・カメラ・Safariのバージョン次第で低くなります。20FPSは上限目標で、実機の測定値ではありません。推論は長辺480pxから開始し、平均処理時間が65msを超えると384px、320pxへ下げます。推論を重ねず、カメラフレームを間引いて処理します。直近の骨格を毎描画で使い、DOMの診断更新は最大4回/秒です。カメラ映像の表示は推論結果とは別に維持します。ただし非常に遅い端末ではWASM処理がメインスレッドを占有し、画面や操作にも遅れが出ることがあります。

SafariではHTTPS、サイトのカメラ許可、WebGL、`muted`・`playsinline` が必要です。メモリ圧迫やバックグラウンド遷移でカメラ／WebGLが中断される場合はStart Cameraで再開してください。画面復帰時に無断でカメラを再開しません。Camera FPSは対応ブラウザでは `requestVideoFrameCallback` の表示フレーム数から計算し、非対応では動画時刻の変化に基づく近似値です。端末のカメラセンサーFPSの直接測定ではありません。iPhone Safariの実機・実際の体育館での性能は未検証です。

### ShotDetector Debug Mode

チェックをオンにし、シュートする手を選びます。Sessionと同じ `ShotDetector.processFrame(timestamp, landmarks)` アダプターを介して、既存の `detectSessionShots` が姿勢だけの候補を判定します。ライブ専用の別のシュート分類器は作っていません。Sessionの一括判定は同じフレームインターフェースで受け取り、元の一括判定と同じ結果を返す回帰テストがあります。

状態は **IDLE / DIP / RISING / RELEASE_CANDIDATE / FOLLOW_THROUGH / COMPLETE**、カウントは **Shots detected**、検出時は **SHOT DETECTED #X** を表示します。状態は準備・上昇・伸展の条件を示す診断表示で、すべての状態が各シュートで順番に表示されるとは限りません。候補の確定には既存のリリース後0.8秒の証拠区間を待ち、計算は約4回/秒です。ライブ時刻はカメラフレームを採ったタイミングで記録し、推論完了までの遅延を速度に加えません。同じ候補を繰り返し加算しないようにします。

実際のSession検出と共通の手首高さ、上昇速度、肘角度・角速度、肩に対する手首の位置を表示し、直近10秒の手首高さを描画します。膝角度は補助表示で、現行検出器の判定には使っていません。カメラの再起動・切替、Debug切替、手の切替でカウントと履歴をリセットします。カメラの映像サイズが変わった場合は座標の異なる履歴を混ぜず、カウントだけ保持します。

体育館では、本当に打った本数とカウントを比べ、見逃した際に「姿勢が欠けた」「DIPで止まった」「RISINGから候補にならない」「FOLLOW_THROUGHで繰り返してしまう」のどれか、手首高さ・肘の伸展量・Pose FPSをメモしてください。改善はこの実測情報を使ってSessionと共通の検出条件に反映でき、Live Poseだけの条件を足す必要はありません。

### 再利用した構成と検証

- `pose-engine.js`：既存MediaPipe Pose Liteのローダー、アセット、オプション、エンジン生成をSingle Shot／Session／Liveで共用。
- `pose-coordinates.js`：contain表示・鏡像・正規化座標を1つの変換にまとめ、Liveと既存の比較／ボール再生で共用。
- `live-metrics.js`：既存の角度計算を使った信頼条件付きの基本計測。
- `shot-detector.js`：既存のSession検出器と同じ信号・閾値を使うフレームアダプター。ライブ履歴・状態・重複防止のみを追加。
- `live-pose.js`：カメラの開始停止、リアルタイム骨格、間引き、性能表示、任意のデバッグ。同じ姿勢エンジンの生成関数を利用します。

`npm test` は68件。座標変換・鏡像・縦横表示、計測の欠測、同一フレームでのSession判定一致、ライブの単発／複数検出・重複防止・姿勢消失復帰を検証します。Single Shotの変更前スナップショットも維持しています。

`npm run dev` の起動後、任意のPlaywright＋Chromium環境で `NODE_PATH=/path/to/playwright/node_modules node scripts/check-live-pose.cjs` を実行できます。`LIVE_TEST_URL`、`LIVE_CHROMIUM_PATH` で対象を指定できます。この確認は疑似カメラと姿勢データを使い、開始停止、背面／前面、権限拒否、開始途中の取消、画面移動時の停止、縦横と高DPIの位置合わせ、姿勢消失復帰、計測・性能表示を検証します。別途、実際のMediaPipeモデルで合成カメラのピクセルを推論し、診断と未検出表示と停止を確認しました。ソフトウェアWebGLの測定値はiPhone性能の指標にはしていません。WebKitの追加検証はブラウザ取得先への403制限で実施できていません。

## Single Shotを維持したSession（アプリ版0.8）

既存のSingle Shot（利用者指定のv0.1の中核フロー）は引き続き独立した画面です。1本をアップロード → Good Form比較 → Form Match・5分類の点数・確認ポイント・フィードバック・比較再生の流れと採点ルールを維持しています。既存の手動区間指定、自動設定、保存動画、履歴も利用できます。アプリは既に0.5のため、Session追加版は0.6、検出・区間再生改善版は0.7、成否の参考推定追加版は0.8です。

**Session** はGood Form登録後、10分以内の練習動画を選んで「Sessionを分析」を押します。全体を12fpsで走査して複数のシュート候補を検出し、各区間を同じ `analyzeVideo` で再分析します。両モードの点数・確認ポイント・コメントは共通の `reviewShot` エンジンから生成し、Session専用の採点基準はありません。全体走査と各区間の再分析で処理時間がかかります。

候補はボール離れを優先し、追跡できない場面では手首上昇・肘伸展から低精度の候補を検出します。準備姿勢から、手首が連続して上がる一連の動作を確認します。姿勢のみの候補は肘の屈曲から伸展も確認します。1フレームだけの飛びや低い腕振りを除外し、次の準備姿勢に戻るまでフォロースルーの揺れを新しい姿勢候補として数えません。0.8では、連続したボール離れ候補は高さや肘の条件を満たさなくても保持します。姿勢のみの候補は手首上昇量・肘伸展量・準備位置の条件を緩和し、上昇中の小さな検出途切れを許容します。1.5秒以内の候補は同一動作としてまとめます。そのため速い連続シュート、ボールの見失い、複数人、歩行やパスでは見逃し・誤検出があり得ます。これは実シュート動画で検出率を検証した分類モデルではありません。無検出時に架空のシュートを作りません。Single Shotで任意の区間を分析できます。

Session結果は1本ずつの時刻・Form Match・信頼度、時系列のスコア一覧、平均・最高・前半対後半の平均差を表示します。未算出の点数は平均から除外し、精度低の参考点数は含めます。各候補の「この1本を再生」は専用プレーヤーで開始から終了まで再生し自動停止します。0.5倍速・0.25倍速、再再生、リリース候補で停止を利用できます。「対象」のチェックを外すと誤検出を本数・平均・推移から除外し、変更は履歴に保存します。旧結果でも再生・除外を利用できます。検出条件を更新して分析し直すには「この動画を再分析」を押してください。各行の詳細から既存のサブスコア・フィードバック・Good Formとの同期再生を開けます。結果と基準スナップショットは動画と一緒に保存し、History（履歴）から再表示・削除できます。

同じ区間・リリース時刻・撮影条件のクリップは共通の計測・採点ルールを使います。別アップロードで動画の再エンコード、フレームの位相、自動推定時刻が変わると多少の差が出ます。厳密な比較にはSessionで検出された区間・リリース位置をSingle Shotにも合わせてください。

Session実装前に `test/fixtures/single-shot-baseline.json` に既存の計測値・Form Match・サブスコア・フィードバック・確認ポイントを記録しました。回帰テストはこれとの一致を検証します。Sessionのテストは複数検出、重複抑制、無検出、姿勢のみの推定、時刻を0に戻した同一クリップの採点一致、集計を検証します。ブラウザでも既存Single Shot、3候補のSession、同一区間のSingle Shotとの一致、比較再生、履歴再読込、区間再生・終了時停止・リリース位置で停止、集計対象の除外と復元、キャンセル、スマートフォン幅を確認しています（姿勢は固定テストデータ、ボール追跡は動画の実ピクセル）。実際の競技動画の精度とは区別してください。

## ゴールが映る場合の成否の参考推定（0.8）

Single ShotとSessionのアップロード画面に、任意の「ゴールが映る場合の成否推定」を追加しました。動画を選び、ゴールが見える位置で停止して「位置を指定」を押します。静止画像上で**リング全体を囲む左上・右下の2点**をクリックしてください。バックボード全体ではなくリングの幅と高さを指定します。ゴールの自動物体認識ではなく、利用者が位置を確認する方式です。固定カメラ向けで、カメラが動く映像には対応していません。

ゴールを指定すると、通常のフォーム分析を維持したまま、長辺最大960px・24fpsでリリース付近から最大4秒先までボール候補を追跡します。Sessionでは次の候補の開始前までに制限し、次のシュートと混同しないようにします。リング付近の連続した下降軌道がリング内側を通過すれば **成功の可能性（推定）**、リングから明らかに横へ外れて下降すれば **失敗の可能性（推定）** を表示します。リングの縁との重なり、遮蔽、追跡途切れ、軌道不足は **判定不能** とします。

ゴールが映らない場合は位置指定を行わず、チェックをオフのまま分析してください。**成否判定なし** としてフォーム分析だけを行い、成否追跡の追加処理も実行しません。ゴールが映っていても未指定なら同様です。追跡処理に失敗してもフォームの結果は保持し、成否は判定不能にします。

成否は2D映像からの低信頼度の参考推定です。リングの手前・奥を通る軌道、遠距離の小さなボール、リングや選手による遮蔽、反射・似た色、暗い映像では誤判定・未判定があり得ます。連続した観測だけを使い、遮蔽区間を補間して成功を決めません。主にオレンジ・茶色のボールに対応します。成否はForm Match・確認ポイントのスコアに加算しません。

Sessionの候補再生では、成否を追跡した区間まで再生し、指定ゴールの枠とボールの輪・軌道を表示します。判定と指定位置は履歴に保存します。旧動画は「この動画を再分析」で指定できます。計算テストは成功・失敗の推定、未指定、縁付近、追跡途切れ、別トラック、上昇軌道、時刻の範囲外を検証しています。ブラウザでも実際にデコードした合成動画のピクセルから、位置指定・追跡・成功の参考判定・軌道表示・履歴保存を確認しています。利用者の実シュート動画での精度や、14本すべての検出は未検証です。

## ブラウザで試す

公開先： https://fumitaka73.github.io/personal-sports-form-lab/

ChromeまたはEdgeを推奨します。姿勢推定にはWebGLが必要です。初回分析で同じサイトからモデル・WASM（約12MB、ブラウザにより異なる）を読み込みます。

1. **01 Good Form**：コーチが評価した自分の動画を選びます。シュート種別（ジャンプ・セット・フリースロー）、撮影角度（正面・横・45度）、シュートする手、メモを入力します。
2. **開始・リリース・終了を自動設定** は初期状態でオンです。時刻を入力せず分析ボタンを押せます。先頭30秒以内を走査し、ボール離れ候補、または手首の上昇・肘の伸展からシュート区間を推定します。どちらも取れなければ区間中央を仮設定します。必要な場合だけ「手動で修正する（任意）」を開き、動画を止めて位置を指定してください。時刻を手動変更すると自動設定はオフになります。
3. **分析してGood Formに設定** を押します。登録完了後、**Single Shot** で別の動画を同様に分析します。
4. **03 比較結果** に一致度、5分類の点数、推定骨格、計測値から生成したフィードバックが表示されます。**リリースを合わせて同時再生** で見比べられます。
5. **履歴** から過去の結果を開けます。**動画・メモ** では旧版で保存した動画も利用できます。

まずは同じ動画・同じ手・同じ区間指定で基準と今回を分析すると、点数の再現性を確認できます。毎回独立した姿勢推定器で処理しますが、ブラウザ・GPUによって推定結果に小さな差が出る可能性があります。

動画ファイルの200MB制限は撤廃しました。保存できる大きさはブラウザの空き容量に依存します。MP4（H.264）/ WebMを推奨します。保存はブラウザ・ホスト・ポートごとに独立しており、ブラウザのサイトデータを削除すると記録が消えます。元の動画は別途保管してください。

## 撮影と分析の限界

- 全身とシュート側の腕が映る、1人・1本のシュートを固定カメラで撮影してください。同じカメラ位置、左右の向き、撮影倍率が推奨です。遮蔽・手持ち撮影・複数人・編集された映像には対応していません。
- 2D姿勢を毎秒12フレーム、長辺最大640pxで推定します。奥行きや関節の回旋、手首の細かな動作、実際の指とボールの接触、成功率は計測しません。ボール候補の2D軌道は表示できます。リリース時刻は自動推定できます。ボールは色・丸い輪郭・連続する位置から候補を追跡しますが、実際の指離れの確定ではありません。
- 検出率が低い・追跡が途切れる・足が映らない・腕の動きが小さい場合も動画を受け付け、見える関節ごとに分析します。これらは拒否条件ではなく「精度低」の表示理由です。姿勢が全く取れない場合も登録・比較再生・履歴は使えますが、数値スコアは未算出になります。検出できない数値を作りません。
- 撮影角度が違う場合、角度・位置・フォロースルーの揺れは除外し、時間指標のみ比較、信頼度はLowにします。同じ角度という選択でも、実際の位置が大きく違えば比較は不確かです。
- シュート種別が違う場合、下半身・跳躍に依存する項目を除外します。ジャンプとセットの自然な違いを点数に入れません。
- 信頼度High/Medium/Lowは検出率・ランドマークのvisibility・比較項目数・撮影条件から決める目安で、誤差確率ではありません。
- **Form Matchは自分の基準との類似度**であり、シュートの絶対的品質や医学的評価ではありません。骨格と映像を照らし合わせて確認してください。実際のバスケットボール映像での精度・有効性の評価は今後必要です。

## 構成

Viteと素のJavaScriptによる静的サイトです。MediaPipe Pose Liteのモデル・WASMをnpmパッケージからコピーし、サイト内で配信します。バックエンドや外部AIサービスは不要です。

```text
src/
  main.js             画面・比較再生・骨格表示
  storage.js          ローカル保存と旧データの移行
  pose.js             フレーム抽出・MediaPipe姿勢推定・追跡の実行
  ball-tracking.js    オレンジ・茶色の丸い領域の検出と位置追跡
  auto-phases.js      ボール離れ候補・姿勢からの区間推定
  metrics.js          姿勢から計測値を計算・基準と比較
  scoring-config.js   指標の許容差と重み
  feedback.js         数値差から1〜2件の助言を生成
  checkpoints.js      指定された8項目・必須3項目の参考評価
  checkpoint-config.js 個人目標の範囲・許容差・未評価の仮置き値
  style.css           レスポンシブ表示
scripts/
  copy-pose-assets.js npm内のモデル・WASMをpublicへコピー
public/pose/          自動生成・Git管理対象外
test/
  metrics.test.js     計測・採点のテスト
```

### 3つの層

1. **姿勢推定**：肩・肘・手首・腰・膝・足首を取得。visibilityが0.2以上の関節を個別に使い、足首や腰が見えなくても肘などの計測を続けます。モデルの検出・追跡閾値は0.25です。リリース近傍の関節が欠けた場合は最も近い検出場面の値を使い、精度低と表示します。映像の縦横比を補正し、近い3フレームの移動平均で小さな揺れを平滑化します。欠けた関節を補完したり、大きな追跡の途切れをまたいで平滑化したりはしません。
2. **決定的な計測と採点**：肘・肩・膝・股関節の2D角度、体幹の傾き、足元に対する上体のずれ、腰の上昇、脚と腕の伸展開始の時間差、腕の伸展から指定リリースまでの時間、手首最高点の時刻、手首の高さ、フォロースルーの手首・肘の揺れを計算します。距離は胴の長さ、時間は開始からリリースまでの長さで正規化します。伸展開始は区間内の角度の最小値から最大値への30%地点の近似です。実際の動きの開始の厳密な推定ではありません。
3. **助言**：比較に使えた指標の差が大きい順に最大2件の練習上の確認点を出します。現在はルールベースで、OpenAI/LLMは未接続です。将来この層だけを差し替えられます。LLMが数値スコアを決める構成にはしません。

### スコア

各指標： `max(0, 100 × (1 − abs(今回 − 基準) / 許容差))`

分類内で指標の重み付き平均を計算し、総合点は下半身20%・バランス20%・肘20%・リリース25%・フォロースルー15%の重み付き平均です。指標や分類が対象外なら残る重みを再配分します。比較可能な指標が1個でもあれば暫定スコアを表示し、項目数と精度低の表示で範囲を明示します。1個もなければスコアは未算出ですが、動画の登録・比較・履歴は続けます。許容差・重みは `src/scoring-config.js` で変更できます。現在の許容差は試作の設定で、検証された競技基準ではありません。

結果には基準と今回の数値・差・許容差・重み・除外理由を表示します。履歴は分析版・計測値・基準情報のスナップショットを保存し、後でGood Formを変更しても昔の点数は変えません。将来の経時比較のため日時と条件も保持します。

## バージョン0.4：8つの確認ポイント

比較結果の先頭に必須の **リリースの高さ・鼻との近さ・反り腰の兆候** を表示し、次の8分類を0〜100点で評価します。これは利用者の指定目標への参考スコアで、Good Form一致度とは別です。

| 確認ポイント | 評価に使うもの / 評価できない部分 |
| --- | --- |
| ディップ：お腹・体に近い・緩いS字 | 手首の低い位置、体との距離、軌道の曲がり方を代用。ボールのS字を検出した結果ではありません。 |
| 鼻・顔に近いセットとリリース | リリース候補時刻に近い鼻とボール候補の高さ・距離（未追跡なら手首を代用）、顔に近づいた場面の肘角度。指から離れる瞬間を確定した結果ではありません。 |
| 腕の内側への入り・ワイパー | 正面/45度で肘が中心線を越える量と手首の横移動。横動画では未評価です。 |
| 肩の水平・右肩が出ていないか | 正面/45度の肩のラインとモデルの奥行き推定。奥行き差は同じ撮影角度のGood Formがあれば基準との差にします。 |
| リラックス・力み | 手首の加速度の急変を代用。筋肉の緊張は直接判定できず、検出の揺れでも悪化します。 |
| 狭めの足幅・反り腰 | 正面の足幅/肩幅と、横動画の肩が骨盤より後ろにある量を代用。腰椎の反り・骨盤の傾斜は計測していません。 |
| ボール持ち・手の接触 | シュート側寄りの手首位置のみ代用。ボールを乗せすぎているか、手のひらがべったり接触しているかは未評価です。 |
| リリース後の指の方向・右側への流れ | 手首がシュート側へ流れる量と、任意指定のゴール方向に対する人差し指の向きを代用。中指はモデルが検出しないため未評価です。 |

**鼻付近のリリースは利用者が指定した目標**で、すべての選手に推奨するリリース位置ではありません。自動設定の候補がずれている場合は、リリース時刻を手動修正してください。体が切れている場合、肩幅または顔の大きさから胴の長さを近似し、カードに明記します。

「ゴールの方向」は動画内の画面右/左/上から任意で指定できます。これは画面内の向きの粗い評価であり、3Dのゴール位置や実際の中指の狙いは評価しません。映像が左右反転している場合は、実際の映像の手・方向と指定が一致しているか確認してください。

### 推定・未評価の区別

- 計測できた項目は、代用した部分を記載して **推定・参考評価** と表示します。「高すぎる」「右肩が前に出ている可能性」「上体が後ろに傾く兆候」など、値が目標より外れた方向のコメントを付けます。
- 情報がない項目にも **50/100** を表示しますが、これは **未評価・仮置き50** です。映像から推定した点数ではなく、平均的・良い・悪いという判定でもありません。姿勢が全く取れない動画に断定的な指摘を出しません。
- 仮置き点数は分類・総合スコアに含めません。計測できた小項目を平均し、鼻・リリースと足幅・腰の分類の重みを3、残りを1にします。全部未評価なら総合も「未評価・仮置き50」です。
- `src/checkpoint-config.js` の個人目標範囲内なら100点、範囲外の差を許容差で割って減点します。S字だけは曲がりが両方向にあれば85点、確認できなければ60点という試作ルールです。これらは検証済みの生体力学・競技基準ではありません。
- 既存の履歴も保存済み姿勢から8項目を表示できます。新しい分析では評価版とコメントを履歴に保存します。新しいモデルや別のカメラで同じスコアになる精度を保証するものではありません。

チェック項目のテストでは、高いリリースで減点、反り腰の代用指標、右肩の方向、未評価項目の除外、全項目の0〜100点表示、同じ入力の再現性を検証しています。実際のシュート・指・腰の状態を正しく判断できるという検証とは別です。


## バージョン0.5：自動区間設定とボール追跡

### 手動入力なしの分析

初期設定では自動区間設定がオンです。動画を選んで分析ボタンを押すだけで、先頭30秒以内を12フレーム/秒で走査します。複数の動作がある場合は、検出条件に最も合う1候補を選びます。1本のシュートだけを含む短い動画が推奨です。

- **ボール離れ候補**：手首・人差し指近傍にあったボール候補が、連続した同一トラックのフレームで手から離れて上昇する場面を探します。最後に手の近くにあった時刻と最初に離れた時刻の中間をリリース候補にします。2Dの重なりと代用ランドマークからの推定で、指の接触を検出するものではありません。信頼度はMediumです。
- **姿勢による推定**：ボール離れを取れなければ、手首の上昇と肘の伸展が大きい場面から推定します。信頼度はLowです。
- **仮設定**：どちらも取れなければ区間中央を使い、Lowと理由を表示して分析を続けます。
- **開始・終了**：候補の前の手首の低い位置と、候補後の手首の落ち着く場面から前後を切り出します。データ不足時は前後の時間幅で近似します。
- **手動指定**：チェックを外すか時刻を入力すれば手動モードになります。手動リリース時刻を自動処理で上書きしません。

結果画面には両動画の採用時刻・検出根拠・追跡フレーム数・離れ候補の区間を表示します。水色の輪と線は検出位置と最近の軌道です。別のトラックや見失った区間は線でつながず、存在しない位置を補完しません。自動設定とボール位置は履歴に保存します。旧履歴は変更せず、追跡を追加したい場合は元の保存済み動画を選んで再分析します。

### 追跡方式と限界

追加の外部APIや学習モデルを使わず、ブラウザのCanvasで長辺320pxの画像から暖色・高彩度の丸い領域を探します。黒いボールの継ぎ目を細い範囲でつなぎ、サイズ・形・手の近さ・前回位置・速度で候補を対応付けます。主な対象はオレンジ・茶色のボールです。これは学習済みのボール識別器ではありません。

白・青・黒などのボール、暗い映像、小さく映るボール、遮蔽・ぼけ・大きなカメラ移動では追跡できないことがあります。服・肌・背景の丸い暖色領域を誤認する可能性もあります。色で検出した**ボール候補**と表記し、確定した物体や正確な指離れとは扱いません。姿勢から手が読めない場合も新しいトラックを開始できません。

リリースの高さ・鼻との距離には、同フレームに信頼条件を満たすボール候補があればその中心を使い、未追跡なら手首を代用します。追跡で追加するのは位置と軌道であり、手のひらの接触、中指、シュート成功率、正確なボール速度・回転は計測しません。12フレーム/秒のため時刻はフレーム間の近似です。

検証では、合成した動画の実際のピクセルから追跡し、時刻を入力せず約1.04秒の離れ候補を選ぶこと、軌道表示・履歴保存・手動修正を確認しました。この検証の姿勢はテストデータです。実モデルで未検出の動画を受け付ける検証とは別で、実際のシュート映像での精度評価は今後必要です。
