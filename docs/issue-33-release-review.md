# v0.21.5 シュートの確認

登録するのは**ボールが手から離れる瞬間（リリース付近）**です。シュート前に膝を曲げるディップの開始ではありません。動画から本人が決める目安で、手とボールの接触を厳密に測定する機能ではありません。

- **候補を確認（クイック）**：AIが拾った候補を1件ずつ再生し、「シュート／違う／あとで」を選びます。
- **全体から探す（全編）**：練習動画と時間軸を見て、検出漏れのリリースを追加します。

どちらでも手動登録・誤検出修正は可能です。操作は同じで、時間軸と候補一覧の見せ方が違います。

## 操作

1. 「先頭」で保存された動画の最初へ移動。「再生」で開始します。読み込み中は「読み込み中…」と表示し、完了すると押せます。
2. 「−3秒／＋3秒」や位置バーでボールを放す場面へ移動し、一時停止します。動画の端を越える移動は範囲内に収めます。
3. 「このリリースを登録」を1タップ。「保存しました」と件数を確認し、続けて次の場面へ移動します。10本以上の連続登録でも選択解除・モード変更は不要です。
4. 読み込み失敗は「再試行」。欠損位置では「次の映像から再生」と表示します。保存動画がなければ「映像なし」で再生できないことを明示します。完了後は「最初から再生」で見直せます。
5. 履歴の再読み込みや検証JSONの書き出しは、従来どおり利用できます。

保存動画の開始がPoseの記録開始より遅い場合、「先頭」は実際の保存動画の先頭へ移動します。大きな未保存区間を0秒の映像として扱いません。最初の50ms以内の記録差のみ吸収し、保存する時刻は実際に表示した映像位置を使います。

縦動画は表示できる画面高さの約30％以内に収め、全身をクロップしません。Safariの画面高さの変化に合わせて映像と骨格を同じ縦横比で描き直します。縦画面は下の操作へスクロールでき、横画面は左右に配置します。

## データ

IndexedDB v4、既存動画・Pose・Good Form・Calibration・レビュー・分析・履歴は削除・初期化しません。新しい手動登録にだけ `timeBasis: release-estimate` を付けます。既存の登録位置は勝手にリリース位置へ変更しません。JSONの新旧ラベル・姿勢書き出しは従来形式を維持し、位置の基準を任意フィールドで追加します。

[検証JSONの詳しい仕様・読み込み方法](issue-31-manual-review.md#検証データを書き出す)も参照してください。書き出しは本人の操作時だけで、動画・姿勢を外部へ自動送信しません。自動学習・検出閾値の変更はありません。

## iPhone Safari実機確認

実機は未検証です。Chromiumで9:16／16:9の合成録画・Pose、320／390／430px縦と844px横、読み込み遅延・エラー、10本連続登録、保存・再読み込み・JSON読込をテストしました。

実機では、カメラで保存した動画を用いて次を確認してください。

- 先頭→読み込み→再生、±3秒の端、エラー時の再試行。
- リリースでの連続登録、件数、再読み込み、JSONの保存リンク。
- 縦横・Safariアドレスバー伸縮・Safe Area、時間軸・登録ボタンへのタッチ、映像／骨格の同期、VoiceOver・文字拡大。
- 候補なし、動画のない位置、Poseのみの記録、既存レビュー・Good Formの保持。

Safari独自のMP4シーク、メディア再生制限、アドレスバー・ピンチ拡大の挙動は実機確認が必要です。サイトデータ削除は不要です。
