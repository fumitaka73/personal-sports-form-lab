## iPhoneでの再テスト（固定編集・診断版）

前回までの実機結果：2分25秒のHomeCourt動画を約1分54秒で骨格解析、ほぼ発熱なし・フリーズなし。取り込み・骨格再解析・マーカー・保存と再読み込みも正常（ユーザー報告）。手動登録とUIはこの修正版で再確認します。

1. **同じURLを再読み込み**し、黄色い「PR41 テスト版 · 固定編集・診断版」を確認。①で**前回の動画**を選びます。サイトデータは消さず、骨格の取り直しも不要です。解析した骨格があれば②の**骨格を使って再解析**で候補を確認します。
2. 動画を再生・停止し、スライダーと**±1秒／±3秒**でリリースに合わせ、**ここがリリース · 追加**。離れたシュートを続けて登録します。現在位置は「分:秒.小数／動画の長さ」で表示します。動画と操作は上部に残り、下だけスクロールします。
3. タイムラインの**○**をタップ。**◎**と「選択中：正解 #番号・位置」が表示され、動画が移動します。**≡**は近い印の一覧です。候補／正解と位置を選んでください。丸の中の数は廃止し、#番号は動画順を示します。
4. 動画を移動し、**#番号をここへ修正**、または**選択を取り消す**を試します。マーカー・本数・保存表示が更新され、取り消しは履歴を残します。同じ位置の二重追加は防止され、追加予定／既存位置を表示します。
5. 保存確認後に再読み込み→同じ動画を選び、登録位置とマーカーを確認。再解析しても正解が残ることを確認します。縦横でも動画を見ながら操作できるか試してください。近接エラーが不自然なら、下の**登録位置の診断 → 診断をコピー**をチャットへ貼り付けてください。動画・骨格は含みません。

HomeCourt動画について、ユーザーが確認した正解総数は**10本**です。HomeCourtの9試投・7成功は参考情報です。10本という総数だけでリリース位置を確定したり、精度を計算したりしません。動画の各リリースを確認してから、⑤⑥の全編確認・比較へ進みます。

Live Coachはテスト用Good Formを登録し、カメラ→音声確認→開始→終了→振り返りを確認できます。本番の基準・履歴はこの環境にはコピーしません。

## 近接エラーの調査結果と診断

旧版 `5afaaea` の390px画面・145秒の人工動画で、20秒に正解を登録後、30秒付近の見かけ上の空白を**実際のタッチイベント**で押すと20秒が選択され、20秒同士の近接エラーになる経路を再現しました。長い動画で透明な44pxの押下領域が広い時間幅を占めること、空白の近傍吸着、モバイルブラウザによるタップ先・クリック座標の補正が関係します。この経路では動画位置・表示・判定位置は20秒で一致しており、保存後に時刻がずれた現象ではありません。

修正版は、実際に触れたPointer座標と見える44pxボタンの範囲で操作対象を決め、空白ではその位置へ移動します。補正されたclick座標だけに頼らず、近くの正解へ暗黙に吸着しません。動画の位置を細かく合わせるには専用スライダーと±1秒／±3秒を使います。

0.5秒未満の制限は維持しています。判定対象は同じ動画の有効な正解だけです。取り消し済みの登録、未確定の自動候補、別動画は対象外です。**別の解析runで人間が確認した有効な正解は、同じ動画の正解として再解析後も有効**なので重複判定に含みます。runを切り替えただけで正解を消したり再追加したりしません。

実機発生時の操作ログはないため、ユーザーの全再発ケースがこの経路だったと断定はしません。診断には動画ID、選択中run、実際の動画位置、表示に使用した位置、シーク要求位置、重複判定の位置、対象の登録ID・由来、無視した取消ID、直近の移動イベント、保存後のID・位置を表示します。新規の追加／位置修正の履歴には軽量な `positionAudit` も残します。以前の履歴は変更しません。診断は自動送信せず、コピー操作をした場合にだけクリップボードへ書き込みます。元動画・骨格・ファイル名は含みません。

## 本番・個人データとの分離

- 新規Sitesプロジェクトの本人限定配信。本番 `fumitaka73.github.io` とは別オリジンです。共有範囲を公開・他人向けには変更しません。
- 保存先も `sports-form-lab-pr41-iphone-test` に固定。本番の `sports-form-lab` を開いたり移行したりしません。同じブラウザ内にあっても、本番の既存Good Form・Pose・動画・レビュー・Calibration・履歴は参照／変更しません。
- テスト用に読み込む動画や録画は、このサイト専用のiPhone内IndexedDBに保存します。テストの動画も端末容量を使用します。
- 公開ファイルは確定したPRコミットのコード・MediaPipe配信アセット・確認用UIのみ。動画・生のPose・レビューJSON・`.env`・認証トークン・作業ディレクトリを含めません。
- Content Security Policyでアプリからの接続先を同一サイトに制限。テスト版のGoogle Drive操作を無効にし、Client IDの設定画面も出しません。既存の本番Drive連携設定は変更しません。ログイン・静的アセット配信の通信はありますが、動画・骨格のサーバー送信は行いません。
- 発熱や端末の実メモリ不足はSafariから直接計測できません。体感・OSの表示・画面の反応を記録します。経過時間は実時間で、推論だけのCPU時間ではありません。
- このテストの結果を本番へ自動同期する機能はありません。更新時も専用URL・保存先名を維持し、初期化や自動削除は行いません。iOSによる退避に備えて原本は写真・ファイルに残してください。

## 再現・検証（開発者向け）

`node scripts/build-iphone-preview.mjs --target <新しい専用Siteの絶対パス> --source <PRコミット>` で再現します。先にその専用Siteの `.openai/hosting.json` に、実際に作成された `project_id` と `static.directory=dist` を保存します。ID・資格情報のハードコードやダミー値による公開はしません。

Gitの確定済みコミットだけをarchiveで取り出し、保存先名・Drive無効化・確認用UI・CSPのみを専用コピーへ追加してビルドします。元リポジトリの機能コード・本番用ビルドを上書きしません。置換対象が一致しない場合や、動画／解析書き出しファイル等が配信成果物にあれば停止します。`test-build.json` に元コミット・アプリ版・専用DB名・外部送信停止を記録します。

Sitesの認証トークン・Git書込資格情報はメモリと非表示stdinだけで扱い、公開物・Git・ログに保存しません。配信用tarは `.openai/hosting.json` と `dist/` のみです。

ローカルの専用ビルドを5192番などで配信し、人工H.264動画を指定して以下を実行します。

```sh
OFFLINE_VIDEO_FIXTURE=/private/path/artificial-14s.mp4 \
  IPHONE_TEST_URL=http://127.0.0.1:5192 \
  node scripts/check-iphone-preview.mjs
```
