# v0.4 動画レビューと修正データ

正式仕様: Personal_Sports_Form_Lab_v0.4_Review_Learning_Spec.md。既存のGood Form、Single Shot、Session、Live Pose、Live Coach、History、Debug Modeを維持して追加した機能です。

## iPhone Safariでの使い方

1. GitHub PagesのHTTPSページをSafariで開き、既存のGood Formを選択します。
2. Live Coachで「動画を一時保存する」にチェックします。初期値はオフです。Start Cameraでカメラを許可し、Start Coachingを押します。「● 録画中」を確認します。
3. Stop Sessionで録画を確定します。Shot Review / Calibrationから各シュートのReviewを開きます。候補が0本のセッションも「見逃したシュートを追加」の対象にできます。
4. 「このシュートを再生」で開始前とフォロースルーを含む区間を再生します。速度を0.5倍／0.25倍にできます。区間の秒数は録画開始からです。開始／終了を変更し「範囲を保存」できます。
5. 必要な区間をKeepにします。「クリップを生成」してからダウンロード、または共有します。指定区間を実時間で再録画するため、画面を開いたまま待ってください。生成非対応の場合は「元区間をダウンロード」を使います。
6. SafariのダウンロードからFilesのダウンロードフォルダを確認します。共有メニューに「ビデオを保存」が出る端末ではPhotosへの保存も可能です。アプリがPhotosへ直接書き込む機能はありません。
7. Shot detectionをCorrect / False Positive、Form evaluationをAgree / Disagree / Unsureに修正します。ディップ、下半身タイミング、リリース、肘、バランス、フォロースルーに適切なラベルを付け、Feedback評価、手動のMade / Missed / Unknown、メモやコーチ原文を保存できます。主観的な0–100評価は客観的なフォーム計測値ではありません。
8. 見逃しはセッションと開始／終了秒を指定して手動追加します。自動スコアを捏造しません。Evaluation & JSONでバックアップできます。動画は別途書き出してください。

## 保存と削除

- IndexedDBの既存DBをバージョン3へ追加移行し、既存storesは削除しません。動画は`temporaryVideos`、分析は既存`results`、修正は`settings/review-v04`です。
- 約15秒ごとにMediaRecorderを停止し、単独で再生可能な動画区間を保存します。保存完了後に次区間を開始するため、未保存データの待ち行列は伸びません。再開始時と保存待ちには短い欠落があり得ます。区間ごとに単調時刻、撮影設定、期限を保存し、ポーズの同じ時刻軸と結び付けます。
- 一時動画全体を約128MiBに制限します。現在の保存量を差し引いて録画し、容量上限／保存失敗時には録画を停止してフォーム分析を継続します。エンコーダの最後のチャンク分は上限を超える場合があります。未完了区間は強制終了で失われる可能性があります。
- 未Keep区間は作成7日後に期限切れとなり、次回起動時に削除されます。Keepは期限切れ削除・未Keep一括削除の対象外です。Keepは同じ元区間を共有する隣接シュートも保護します。
- Discardは選んだクリップと重なる元区間を削除するので、同じ区間の別シュートも動画が利用できなくなります。画面で確認を求めます。Keep区間の削除には「保存を確認したKeep区間も削除」で、必要な動画を端末へ保存済みであることの確認が必要です。
- 書き出し／共有では元データを削除しません。Keep一括書き出しは保護した**元区間**の複数ダウンロードです。シュート単位のクリップは個別生成です。Safariで複数ダウンロードが拒否された場合は個別に保存します。
- 個別生成はcanvas captureStream + MediaRecorderを使用し、30秒以内の指定区間を動画のみで再録画します。音声は含みません。対応MIMEは動的検出します。生成した動画のURLは画面を閉じるまで有効です。
- ブラウザをバックグラウンドにするとLive Coachセッションを終了し、保存できた区間を残します。再開時は新しいセッションを開始します。再読み込みや強制終了の記録は履歴で中断として表示されます。
- ローカル限定で、動画／メモ／コーチ原文をアップロードしません。GitHub Pagesには保存しません。端末間同期はありません。iOSによるサイトデータ削除やプライベートブラウズ終了にはKeepも耐えられないため、動画とJSONのバックアップが必要です。

## 修正と将来の改善

元の分析、Form Match、信頼度、ルール版、Good Form参照、助言、検出イベントは修正とは別に保持します。修正ごとに時刻付きの以前のラベルと動画範囲を保存し、「前の修正に戻す」も新しい履歴として記録します。JSONは既存schema v1の追加フィールドで後方互換性を保ち、動画バイナリは含みません。インポートは既存IDを上書きしません。

Precisionは確認済みの自動候補だけを分母にします。手動追加した見逃しを自動検出TPに加算しません。Recallは全区間検証済みの実本数と候補の確認ラベルが揃ったセッションだけで算出します。未確認は負例ではありません。コーチコメントの一致率と、自分のFeedback評価の件数を別に表示します。

MediaPipeやOpenAIモデルは修正から自動学習しません。閾値のデータに基づく提案、承認適用、検証例による比較、版管理とロールバックを伴うキャリブレーションは**Phase 2（未実装）**です。今回の修正データは今後の検証・改善の材料になります。

音声は「リリース低い」「リリース高い」「ディップ浅い」「ディップ深い」「いいね」など、1シュート1つの短い日本語です。Dipフォーカスを追加しました。Good / Perfectの初期音声閾値は82 / 93で、セッション開始前に変更できます。これはForm Matchの計算を変更しません。低信頼度ではフォーム修正を指示せず、称賛の連続抑制と既存の音声キャンセルを維持します。

## 確認

自動テスト: 既存10テストファイルと、新規temporary-videoテストを実行。形式検出、録画停止・保存完了、保存失敗、Keep期限保護、修正の独立性、JSON移行、見逃しのPrecision/Recall、音声閾値と点数の独立性を確認します。本番ビルドも実行します。

Chromium: モバイル幅で全既存モードの画面遷移、実際のcanvas動画録画／IndexedDB保存、シュート再生、クリップ生成、Keep、修正保存／再読み込み、手動見逃し追加を試験します。実カメラのシュート検出やiPhone Safari実機の合格を意味しません。

iPhone Safari実機では以下を確認してください。

- 30秒程度で3本撮影: 録画表示、各動画の再生、前後余白、0.5倍、生成／共有／Files保存を確認。
- 数分撮影: 姿勢推定と音声の応答、15秒区間境界をまたぐ動作、保存量表示を確認。
- 少ない空き容量: 録画が停止し、動画なしの理由とフォーム結果が残ることを確認。
- ホーム画面へ移動、画面ロック、回転、カメラ切替、タブ終了: 中断後の保存済み動画と時刻のずれを確認。
- 見逃し／誤検出: 手動追加とFalse Positive、原文メモ、履歴／Undo、再読み込み、JSON往復を確認。
- Keepした動画: 未Keep一括削除や期限切れで消えないこと、保存確認後の明示削除でのみ消えることを確認。
- 旧Good Form・Single Shot・Session・Live Pose・History・Debugを開いて既存データが残ることを確認。
