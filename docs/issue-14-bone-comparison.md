# v0.19.1 左右ボーン比較

## 原因と変更

従来のディップは膝角度の最小値で、ボールを下げる動作ではありませんでした。ディップ位置が取れなくても構えへ戻り、フォロースルーは保存末尾へ移動していました。動画そのものが小さいまま、骨格だけを重ねていました。

今回の比較では以下を行います。既存の分析スコアや膝の屈曲指標、姿勢データを再計算して保存する変更ではありません。

- **ディップ**：保存されたボール追跡が十分なときは優先。下降→上昇を中央値で平滑化して探します。取れなければシュートする手の手首の下降→上昇を人物の大きさに応じた幅で探し、「手首から推定」と表示。膝は使いません。低信頼・欠損・単発ノイズでは特定不能を表示します。
- **フォロースルー**：リリース後、肩・肘・手首が見え、肘の伸展（150度以上）と腕を上げた保持が3フレーム、0.08〜0.35秒続く位置を探します。末尾とは別です。あくまで姿勢からの候補で、ボール離れや手首のスナップそのものは判定しません。
- **リリース**：既存の推定／指定時刻を維持。新しいボール離れの実測ではありません。
- **人物ズーム**：左右別々にショット全体の信頼できる姿勢の和集合を取り、余白を加えて固定した範囲を使います。フレームごとに追従せず、揺れを抑えます。元の各軸の範囲の最低25%を残し、極端な拡大を抑制します。端は範囲をクランプ。低信頼、姿勢不足、大きな人物位置ジャンプ、複数人物と記録されている場合は全体表示です。
- 映像とボーンを同じCanvasに同じクロップ・contain・鏡像の座標変換で描きます。映像のシークが未完了の間は古い映像を重ねず「映像を同期中（骨格のみ）」と表示します。端末回転では表示枠を再計算し、保存動画のデコード済みの向きを使用します。
- 左右の表示倍率を示します。倍率・撮影角度が違う映像から身体の実寸やフォームの優劣を断定しないでください。

## iPhoneでの操作・実機確認

1. 「シュートの確認」で1本を開き、「基準フォームと左右で見比べる」を展開します。
2. 遠くに映る基準動画で、人物が拡大され、肘や足に骨格が重なるか確認します。「人物にズーム」をOFFで全体へ戻せます。
3. ディップ→リリース→フォロースルーを順に押します。左右それぞれの動作の時刻が表示されることを確認。位置が取れなければ理由が出ます。
4. 動作位置を手動指定する場合は「保存区間全体で位置を探す」を押し、スライダーで映像を探し、各側の「動作位置を手動指定」で指定します。比較を閉じると指定は解除されます。元のレビュー／解析時刻は変わりません。
5. 鏡像表示、骨格ON/OFF、片側表示、少し前／後、同期コマ再生を試します。縦横回転、Safariのアドレスバー表示状態、320px幅でボタンが押せるか確認。
6. 実際のiPhone MP4、複数区間をまたぐ動画、左右手、欠損・Lowの旧記録で試してください。旧レビュー、メモ、AI改善の承認／元に戻す、JSON入出力も確認します。

## 範囲と制限

- 実機iPhone Safariは未確認です。ブラウザ検証はChromiumと合成姿勢・MediaRecorder動画。実MP4の回転メタデータ、デコード遅延、電池消費は実機確認が必要です。
- Live Coachの軽量姿勢記録はボール追跡を持ちません。保存動画の分析で追跡された場合のみ使用し、それ以外は手首の代理です。
- MediaPipe Poseは1人物の骨格です。映像中の人数を新しく数える機能はありません。人物切替の大きなジャンプ等は全体表示にしますが、すべての複数人物・人物取り違えを識別できません。全体表示と映像確認を使ってください。
- 推定不能な動作のボタンは理由を示し、構え／末尾に黙って移動しません。スライダーでは保存区間の利用可能なコマを確認できます。姿勢の空白を補間して骨格を作りません。
- 手動位置は今回の比較中のみ。IndexedDB変更、保存動画の加工、破壊的移行、スコア／Calibrationの再保存はありません。
- 同期は動作フェーズ間の静止コマ比較です。実FPS単位の再生や音声同期ではありません。

## 検証

`npm test`、`npm run build`、`scripts/check-issue-14.mjs`と既存のレビュー／Calibration／練習履歴のブラウザ回帰を実施。手首・ボールの下降上昇、左右手・鏡像、膝のみの屈曲、ノイズ・Low・欠損、人物クロップ・倍率制限、別時刻の動作同期、動画分割シーク、手動位置、設定保持を確認します。合成テストは実動画での検出精度の保証ではありません。
