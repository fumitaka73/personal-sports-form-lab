# v0.4 — Shot Review, Calibration & Coach Feedback

Application release: VERSION 0.11.0. Measurement/score version remains `basketball-0.5.0`: this release does not change detection or scoring rules. Existing Good Form, Single Shot, Session, Live Pose, Live Coach, History, camera diagnostics and ShotDetector Debug Mode remain available.

## Use

Open **Shot Review / Calibration**. Individual review links also appear in Single Shot comparison results, Session rows and Live Coach summaries/history.

- **Shot Review** shows the original Form Match, confidence, group scores, metric values, deltas, tolerances, original selected app feedback/reason and recorded start/release/end timeline. Missing/excluded measures are N/A. Live timelines display seconds relative to that motion’s start; recorded analysis timestamps remain unchanged. Original stored video can be replayed within the shot window. Live Coach and JSON-only records have no camera video.
- Label detection Correct / False Positive (or leave unreviewed), form evaluation Agree / Disagree / Unsure, and actual outcome Made / Missed / Unknown. Add personal notes and save. These are manual observations, not validated scoring ground truth. They do not change scores, automatic made/missed estimates, live advice, or the existing Session inclusion checkboxes.
- Add human coach name and original comment, observed issue, priority correction, practice cue, agreement with app advice, and optional subsequent improvement notes. Original statements are stored verbatim. Other fields are manually entered summaries, not app/AI interpretations. The app feedback at comment time is saved separately.
- **Good Form Calibration** lists reference type, camera angle, shooting hand, measurement quality, analysis version and ID. Filter by type/angle and select an active reference before Single Shot/Session analysis. Live Coach keeps its own reference selector. New Good Form uploads are registered automatically; previously analyzed videos can explicitly be added as references. Imported measurements can serve as a reference without the source video.
- **Coach Feedback Library** attaches comments either to a shot or to a full Session/Live Coach record. Session comments include a snapshot of session app feedback. There is no OpenAI call or automatic interpretation.
- **Evaluation & JSON** contains reports, full-session manual counts, and export/import. Annotations and imported measurement-only cases remain reviewable after their original analysis/video is deleted.

## Calibration and history

The shared analyzer continues to use normalized geometry and existing tolerances/weights. Different camera angles exclude all non-temporal comparisons and lower confidence; different shot types exclude lower-body and jump-dependent features. Different hands and weak pose evidence lower confidence. Unavailable metrics have null values/scores, displayed as N/A; they carry no scoring weight. An entirely unavailable comparison remains unscored. Personal checkpoint placeholder scores from previous releases are unchanged; they are separate from Form Match.

Good Form registry entries snapshot the reference's original metadata and analysis. Old results and coaching cases snapshot the baseline used at analysis time, plus the score version and reference ID. Choosing, registering or importing a reference does not recalculate historical results. A new analysis creates a new result. The existing optional live confidence policy (estimated release time, capped at Medium) remains unchanged.

## Data model and backward compatibility

No database schema upgrade or destructive migration is required. Existing IndexedDB `sports-form-lab` version 2 stores remain intact. The additive `settings` record `review-v04` stores:

```text
{
  version: 1,
  cases: { [caseId]: CoachingCase },
  references: { [referenceId]: GoodFormSnapshot },
  sessionFeedback: { [mode + ':' + sessionId]: { comments, appFeedback, ... } },
  verification: { [mode + ':' + sessionId]: { actualShots, complete, updatedAt } }
}
```

Existing records without new fields are read lazily; no old record is rewritten to populate annotations. Cases have deterministic IDs (`single:<resultId>`, `session:<sessionId>:<number>`, `live:<sessionId>:<number>`), source links, metadata/timestamp, compact shot analysis/pose metrics, original comparison, score version, Good Form snapshot, rule-generated feedback, manual labels and human feedback. Raw live camera frames/video are not stored. `aiInterpretation` is separate and null; no new AI interpretation or Coach Profile is generated.

New original analysis records also explicitly record score version and reference ID; older records retain their existing comparison.version/reference links. Good Form creation saves its video, active pointer and registry atomically. Annotation/import writes are transactional; failures do not replace the current UI data. Source notes and original analyzed results remain unchanged.

## Evaluation definitions and limitations

- Overall precision mixes all modes, with separate mode counts/precision also displayed. Single Shot labels validate supplied clips, not automatic multi-shot detection. Precision = manually labeled Correct / (Correct + False Positive). Unreviewed predictions are excluded; counts are displayed. These are user-reviewed predictions, not an independently audited test set.
- Recall requires an independent actual shot count, the user's confirmation of reviewing the entire session, and a detection label on every predicted candidate in that scope. Recall = Correct / actual shots; false negatives = actual shots − Correct. Impossible counts (Correct > actual) are rejected from the calculation. Incomplete scopes and zero denominators display N/A. Zero-candidate sessions can be manually verified as complete and report zero recall when actual shots > 0. This is count-based evaluation, not automated frame-level matching; users must avoid marking duplicate predictions as distinct true shots.
- Coach agreement = Agree / (Agree + Disagree), measured per submitted coach comment, including session comments. Unsure is excluded; multiple comments/coaches count separately. This is subjective agreement, not a model correctness probability.
- Form Match uses bins 0–19, 20–39, 40–59, 60–79, 80–100, plus N/A. Confidence counts are reported separately; low-confidence numeric reference scores remain in the distribution.
- Frequent corrections are grouped by shot type and metric. Live uses the recorded trigger (Good/Perfect are not corrections). Legacy Single Shot/Session use the worst eligible metric with score < 90. Low-confidence cases are excluded from correction frequency. Mixed camera conditions and scoring versions are disclosed; the report does not claim improved accuracy, fatigue or causation.

## JSON migration

Download exports `schema: sports-form-lab-review`, `version: 1`, timestamp and all current cases/reference snapshots/comments/verification. Exported cases contain measurements, original app feedback and human statements/labels. References include their stored pose evidence to support confidence-aware comparison after import. Source video/audio blobs are intentionally omitted; keep original videos separately. Imported cases are available in Shot Review, not recreated as original video uploads/Session playbacks.

Import validates schema, IDs/source links, enums, measurements, text and structured feedback before saving. Unsafe prototype keys, unsupported versions and malformed data are rejected. Limit: 50 MiB, 10,000 cases, 500 references, bounded nesting/node count. It merges only new IDs across all collections; conflicting IDs retain local records and the UI reports counts. This avoids silent overwrite of local labels/comments. Imported data remains supplied data; validation is structural, not proof of biomechanical truth. No upload or paid API is involved.

Browser storage can be cleared/evicted; export regularly. A JSON file contains personal coaching information and should be kept where the user intends to store it. Large JSON import/export temporarily uses memory on the browser's main thread; this is a local migration tool rather than a live-camera operation.

## Validation

```sh
npm test
npm run build
# Start npm run dev; install Playwright separately and set NODE_PATH:
NODE_PATH=/path/to/node_modules node scripts/check-shot-review.cjs
# Optional known valid WebM fixture exercises bounded replay too:
NODE_PATH=/path/to/node_modules REVIEW_TEST_VIDEO=/path/to/shot.webm node scripts/check-shot-review.cjs
NODE_PATH=/path/to/node_modules node scripts/check-live-pose.cjs
NODE_PATH=/path/to/node_modules node scripts/check-live-coach.cjs
```

Automated checks cover linked three-mode cases, immutable history/labels, reference categories, JSON round trips/conflicts/malformed data, precision/recall prerequisites, human agreement denominators, confidence/distributions, and the pre-Session Single Shot regression baseline. Chromium integration covers old records, bounded shot replay, annotations without rescoring, original coach text/HTML escaping, session comments, calibration/imported references, real JSON download/import, mobile layout and reload persistence. Existing Single Shot/Session/Live browser regressions were also exercised.

GitHub Pages remains a static build with local model assets and no server/API dependency. Browser checks use synthetic pose/camera fixtures or saved fixture video. Physical iPhone Safari and real practice data have not been tested in this environment; no new accuracy claim is made. Use actual session counts, review uncertain predictions and coach disagreements before making changes to scoring or coaching rules.
