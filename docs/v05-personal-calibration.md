# v0.5 Personal Calibration（アプリ VERSION 0.13）

v0.4で蓄積したレビューを、Live Coachの姿勢によるShot Detectionと短い助言のルールに接続します。候補を比較しても自動適用しません。独立した検証側でも改善した候補だけを承認できます。MediaPipeの再学習、Form Match採点式の変更、過去の結果の再採点は行いません。

## iPhone Safariでの操作

1. 同じSafari・同じ公開URLを開き、再読み込みして「Personal Calibration」が表示されることを確認します。Safariのサイトデータは削除しないでください。既存のGood Form、動画、分析、レビューを引き継ぎます。
2. Live Coachの「検出改善用の姿勢時系列をこの端末に保存」をオンにして練習します。動画の一時保存は別の選択です。見逃しやリリース時刻を確認する練習では動画も保存してください。
3. 練習終了後、Shot Reviewで各候補の検出を確認し、誤検出を修正し、見逃したシュートを手動で追加します。音声には「役立つ」「不正確」「繰り返し」などのラベルを付けます。
4. Personal CalibrationでGood Form・種別・角度・手を選び、別々のセッションを学習用／検証用に割り当てます。最初の比較で実際に評価された割当は固定されます。データ不足で評価できなかった場合は割当を変更できます。
5. 検出の比較には「各シュートの時刻を確認」で全区間の実際の本数と各リリース時刻を確認します。保存された姿勢区間の開始が0秒です。動画が途中から始まる場合、動画の0秒と一致しません。分からない時刻を推測して確認済みにしないでください。元の分析の時刻は変更しません。
6. 検出または音声の候補比較を実行します。表で変更前後の学習・検証結果と候補設定を確認します。改善が確認できた場合だけ「この改善案を承認して次回から使う」が有効になります。
7. 承認後、同じ撮影条件・同じGood Formの次回Live Coachからその版を使います。開始画面に使用版が表示されます。実際の本数・助言を再確認してください。「標準ルールに戻す」または保存した版への復帰も可能です。

「保存済み動画・メモ」は従来のアップロード済み動画とメモを管理するタブです。Live Coachの練習動画と各シュートの確認はShot Reviewを使います。

## 実装範囲と推奨条件

- 初期対象はLive Coachです。アップロード動画のSessionとSingle Shotの検出・分析は標準ルールを維持します。
- 同じGood Form、シュート種別、カメラ角度、手ごとに評価・適用します。撮影条件を修正したレビューが元のセッション条件と一致しない場合は評価から除外します。
- 検出：学習・検証それぞれ2セッション以上、実シュート20本／10本以上。全候補の確認、全区間の見逃し追加、各シュートの時刻確認が必要です。
- 音声：学習・検証それぞれ2セッション以上、対象ラベル20件／10件以上。Correct、手動追加以外、Medium／HighのLive Coach結果を対象とします。
- 候補は学習側だけで選びます。その1候補だけを検証側で評価し、検証結果を見て別候補に乗り換えません。同一セッションを両側に使えません。
- 検出の改善条件は両側でF1が0.005超改善し、誤検出数と見逃し数が増えないことです。正解リリースの±0.5秒以内で1対1に対応付けます。
- 音声は両側で役立つ整合件数が減らず、不正確・繰り返しの合計が減り、各項目と未知件数が増えないことを要求します。単に発話を止めるだけで役立つ助言を失う候補は推奨しません。
- 小さい検証セットでの改善は将来の精度保証ではありません。繰り返し調整すると同じ検証データへの偏りが生じ得るため、新しい別日のセッションでも確認してください。

## 何を変更するか

検出候補は手首上昇幅（0.22／0.35）、肘の伸展差と伸展角（5°・90°／12°・110°）、動作の強さ（0.08／0.18）の少数の閾値セットです。標準値または現在の適用版から対象閾値だけを変更します。学習モデルや無制限の探索は使いません。

音声候補は意味のある差の閾値（許容差比0.15／0.30）、助言項目の優先度（学習側の同じ項目の役立つ／不正確が5件以上ある場合0.75／1.25）、修正助言の反復抑制（3本・6秒）です。画面の助言は残し、読み上げの繰り返しだけを抑制できます。Good／Perfectの手動閾値と元のForm Matchスコアは変更しません。

音声評価は過去の同じ項目・方向のラベルと、一部の項目別ラベル（膝の曲げ、リリース高さ、タイミング）による整合性の再評価です。新しい助言を実際に聞いたときの役立つ度は未測定として扱います。未知の効果を推定して良い評価にしません。

## 保存と端末負荷

IndexedDB `sports-form-lab` をversion 3から4に更新します。既存のストアは保持し、次を追加します。

| 保存場所 | 内容 |
| --- | --- |
| `poseSessions` | 姿勢保存の区間、条件、件数、完全性、使用Calibration版 |
| `poseChunks` | 相対時刻・縦横比・姿勢有無・必要14関節のx/y/visibilityのFloat32 |
| `calibrations` | 承認日時、条件、変更前後の評価、学習／検証ID、パラメータ、前版ID |
| `settings/calibration-datasets-v05` | 学習／検証割当、固定日時、検証用の正解リリース時刻とラベル指紋 |
| `settings/active-calibration:<条件>` | 次回セッションで使う版ID。標準に戻すとnull |

姿勢は最大20fps、100フレーム単位で保存します。約0.21MiB/分、姿勢領域の合計32MiB、1回60分までです。動画とは独立し、動画のKeep／期限切れ／削除で消えません。保存が追いつかない・容量不足・回転・中断などの不完全データは検出評価に使いません。上限で自動削除せず、練習は続行します。

比較は別Workerで実行し、姿勢は1フレームずつ展開します。1セッション30,000フレーム、比較1回の姿勢8MiBまでです。上限超過では比較を停止し、保存データは保持します。時系列は最大20fpsのため当時の実時間検出と完全一致しないことがあります。

Calibration Versionは追加保存し、元の版を上書きしません。承認した版と適用ポインタは同じトランザクションで保存します。セッション開始時に使用版と設定を固定し、途中で設定を変えません。元のForm Match・分析・レビュー履歴はそのままです。承認時にレビュー・割当・適用版が比較時から変わっていれば再比較を要求します。

## バックアップと旧データ

姿勢は各セッションの`.pose`、CalibrationはJSONで別々に書き出せます。修正ラベルは既存Shot ReviewのJSON、必要な動画は既存の書き出し機能で保存してください。iOSがサイトデータを消す場合に備え、端末外にもバックアップを保管してください。

姿勢の取り込みはサイズ、構造、時刻、関節値、件数を検証し、同じIDを上書きしません。Calibration JSONは版の記録を追加しますが自動適用しません。JSONには割当・時刻も記録しますが、取り込みではそれらを自動復元せず再確認を求めます。取り込んだ版は直接適用できず、その端末のデータで再評価する必要があります。

旧v0.4の動画、分析、レビューは維持します。旧セッションに全区間の姿勢がなければ、検出閾値の再検証には使えません。十分な既存音声ラベルがあれば音声候補の比較は可能です。古い動画から姿勢を再抽出する機能はこの段階では追加していません。

## 検証

Nodeテストでは姿勢の圧縮・復元、容量／保存失敗、1対1対応、学習だけの候補選択、独立検証での改善／悪化、データ不足、ラベル変更の失効、重複セッションの拒否、音声の有益件数維持、パラメータ範囲、原データ非変更を確認します。既存Single Shot・Session・音声・動画・レビューの回帰テストも実行します。

ブラウザ検証は合成ラベルと模擬カメラを使い、旧DBからの更新、候補承認、次回セッションへの適用、標準／過去版への復帰、動画なしの姿勢保存、姿勢バックアップ復元、データ不足による承認禁止、元データ保持を確認します。物理iPhone Safariと実シュートでの精度は未検証です。

再現用ブラウザチェック（Playwrightは別途用意、開発サーバー起動後）：

```sh
NODE_PATH=/path/to/node_modules node scripts/check-personal-calibration.mjs
```

`APP_URL`と`CHROMIUM_PATH`で開発URLとChromiumの場所を変更できます。合成fixtureのみを使用し、実際の個人データは送信しません。
