# iPhone向けレビューとAIの改善（Issue #1）

## 使い方

1. **Good Form**で良い動画を選び、種別・角度・手を指定して「分析してGood Formに設定」。現在の基準の動画と管理・選択を同じ入口から開けます。低信頼度でも登録できます。推定リリースは動画で確認し、任意の手動時刻で再分析するか、全身と腕が隠れない同じカメラ位置で撮り直してください。
2. **Live Coach**でカメラ→コーチングを開始します。姿勢記録は動画のチェックに依存せず自動保存します。練習後に動画を確認したい場合は「動画を一時保存する」もONにしてください。終了して保存完了を確認します。
3. **Shot Review**の未確認一覧からシュートを開きます。「合っている」などを選び「保存して次へ」の2タップで確認できます。シュートの有効性だけを確かめる専用ボタンと、誤検出ボタンは1タップです。2つの指摘はそれぞれ正しい／違う／判断できないを選べます。これらはForm Matchへの納得度や「役立つ」と別のラベルです。詳しい数値、点数への納得度、メモ、コメントは「詳しく修正する」に残っています。
4. 見逃しは一覧下の「見逃しを追加・動画の保存管理」から秒数を入力します。手動追加には自動スコアを作りません。動画は再生の下の「切り出し・保存・共有」からKeep、切り出し、ダウンロードできます。
5. **AIの改善**で不足件数を確認して「AIの改善案を作成」。使える項目だけ検証し、検出・音声を別々の改善案として表示します。保存情報の正確さも検出比較時に確認します。「この改善案を適用」で明示的に承認したものだけ次回のLive Coachに反映します。見送っても現在のルールは変わりません。「以前の設定に戻す」から標準／過去の版へ戻せます。
6. 検出評価用の全区間・リリース時刻確認、割当の手動変更、保存状態の確認、履歴、JSON/.poseバックアップは「詳細設定・データ管理」。Single Shot、Session、履歴、保存済み動画・メモはトップの「その他」にあります。

レビューだけでは自動学習しません。MediaPipeの重み、Form Matchの採点、腰の代理指標の閾値を学習する機能ではありません。

## 姿勢「0.00MiB」の調査結果

コードで確認できたこと:

- 以前のMiB小数2桁表示は、実際に保存した数KiBも0.00と表示していました。新表示はB／KiB／MiBとフレーム数です。
- 以前は最初の約100フレームが停止までメモリに残る場合がありました。初回フレームから書き込み、以後は約1秒または20フレームで保存します。
- 以前は動画の停止を待ってから姿勢を終了保存していました。現在は独立した終了処理です。
- 以前は書き込み前に保存量を増やしていました。現在は成功した分だけ増やし、容量不足／遅延／未取得／書き込み失敗を表示します。
- セッションと姿勢のIDは同じIDから生成されています。動画から姿勢を復元したり、compactAnalysisに残らないフレームを捏造したりする処理はありません。
- v0.5以前、姿勢保存をOFFにした過去の記録、途中でSafariが終了した記録には姿勢がないことがあります。保存途中の記録は完全な検出検証データとして扱いません。

スクリーンショットの実データはこの開発環境にないため、その個別記録がどの原因だったかは断定できません。詳細設定の「保存状態を確認する」で実際のチャンク容量・フレーム数・ID不一致を確認できます。iOSによる強制終了やストレージ消去を完全に防ぐことはできません。

## データ互換性・安全性

IndexedDBは引き続きバージョン4、既存ストア・ID・結果・動画・レビュー履歴・設定版を削除しません。レビューJSONのスキーマバージョン1に任意の `voiceJudgment` と `cueLabels` を追加し、履歴とともに検証・往復できます。以前の助言評価ラベルも使えます。点数・元の分析・コメント原文は上書きしません。

割当はセッション単位です。既存の確認用記録を改善用へ移しません。自動割当はレビューの利用可能件数を使い、判定精度や確認用の成績から割当／候補を選びません。候補は改善用だけで選び、その1案を確認用で検証します。各側2セッション以上、改善用20件／確認用10件という実装済み条件に沿って不足件数を表示します。検出は完全な姿勢と人が確認した時刻、音声は正しい検出・十分な信頼度・一致する条件・評価ラベルが必要です。改善未確認の案は適用できません。

承認した検出と音声の設定は別々に適用し、他方の設定を保持します。レビュー・割当・対象の現在設定が変わった案は再検証が必要です。判定設定の履歴と適用ポインタは同じトランザクションで保存します。

## テスト・iPhone Safari手動確認

自動確認は合成データで行い、個人の動画や練習データをコミットしません。

- `npm test` / `npm run build`
- `NODE_PATH=<Playwrightのnode_modules> node scripts/check-issue-1.mjs`: 自動割当、検出と音声の1ボタン作成・独立承認、復帰、2タップ確認、2項目の修正、誤検出、見逃し、別タブ競合、320/390/430px縦画面。
- `scripts/check-personal-calibration.mjs`: 旧IndexedDB v3→v4、元データ維持、実際のWorkerで検出・音声の検証、承認・復帰、録画OFFのカメラで姿勢保存、.poseバックアップ復元。
- `scripts/check-shot-review.cjs`: 3分析モード、ラベル・コメント・基準管理、集計、JSON往復、元データの保持。
- `scripts/check-coach-review-ux.mjs`: 腰の既存指標ラベル、設定維持、Good Formへの統合導線、390px縦画面。
- 追加単体テスト: 小さい保存量、容量エラー・空記録、ID不整合、偏った件数での割当、固定・手動割当の保持、長い／1フレーム.pose。

実機iPhone Safariでは、PRをマージしてPagesが更新された後、同じURL・通常ブラウズでページを再読み込みしてください（履歴やサイトデータを消さない）。既存履歴を確認→動画OFFで短い練習を保存→姿勢B/KiB・フレーム数が増えることを確認→動画ONで撮影→レビューと共有→改善案の承認・以前の設定への復帰を確認してください。縦画面で下端のボタンがSafariのバーに隠れないかも確認します。ホーム画面から戻る／画面ロックで終了保存されるか、空き容量が少ないときに警告が出るかを確認してください。

制限: ブラウザ自動テストはChromiumで、実機Safariの録画・音声・共有・中断は未確認です。古い欠損姿勢の復元、検出用時刻の自動正解認定、MediaPipeの再学習は行いません。改善案は画面を離れると再作成が必要ですが、既存データ・割当・承認した設定の履歴は保持されます。比較1回8MiB・1セッション30,000フレームの処理上限を維持します。.poseの読み込み上限は頻繁な保存に合わせて拡張し、古いバックアップも読み込めます。
