# v0.19.3 左右ボーン比較

## 変更前と変更後

以前は映像の下に秒数・倍率・推定根拠・範囲指定ボタンが並び、コマ更新で文章の長さが変わっていました。今回は左右の映像、固定高さの短い状態表示、主要操作を一つの比較ワークスペースにまとめています。秒数は画面に表示せず、内部の同期用時刻はそのまま保持します。同じ状態文は書き直さず、350ms以内の短い待ちでは「読み込み中」へ切り替えません。

画面を開くと比較部分まで移動します。映像と主要操作はまとめて追従します。縦画面は3列×2行のボタン、横画面は6列で高さを抑えます。動画高さは動的ビューポートに合わせ、Safe Areaと既存のヘッダー・下部ナビゲーションに余白を確保しています。主操作は44px以上です。

## iPhoneでの操作

1. Shot Review、またはAIの改善から対象シュートを開き、「基準フォームと左右で見比べる」を開きます。
2. 「ディップ」「リリース」「フォロー」で動作位置を切り替えます。「フォロー」はフォロースルーです。
3. 「再生／一時停止」「前のコマ」「次のコマ」、位置スライダーで映像と骨格を一緒に確認します。
4. 骨格の表示、人物ズームのON/OFF、片側表示は「表示設定・詳細操作」を開きます。
5. 各側の「詳細」には推定根拠、倍率、人物範囲、手動範囲指定、保存、鏡像、動作位置の手動指定があります。
6. 手動範囲は「人物の範囲を指で囲む」を押してから、映像の人物をドラッグしてください。範囲指定と動作位置指定の機能は従来どおりです。

## データ保護

DBスキーマ・動画・分析結果・レビュー・Calibration・練習履歴は変更しません。比較表示だけを変更し、再分析や初期化は行いません。基準動画の手動範囲を明示的に保存する既存機能は維持しています。PR #17の二重フレームバッファと左右同時更新は維持し、読み込み中も直前の映像と対応する骨格を保持します。

## 検証と制限

単体テスト、ビルド、新しいIssue #18ブラウザテストと既存の左右比較・人物拡大・レビュー画面のテストを実施。Chromiumの模擬画面で320×568、375×667、390×844、430×932、844×390を確認し、長文状態・連続更新・遅延デコード・区間境界・操作サイズ・設定保持を検証します。

実機iPhone Safari、実際のアドレスバー伸縮・ノッチ・端末独自の動画デコードは未検証です。PRの環境で次を確認してください。

- 縦横回転・アドレスバー開閉で左右映像と主要操作が同時に見え、下部ナビに操作が隠れないこと。
- 再生・連続コマ送り・スライダードラッグで秒数の点滅や高さの変動がなく、遅い読み込みでも映像と骨格が一緒に保持されること。
- 詳細を開閉し、鏡像・片側表示・手動範囲とその保存・手動動作位置を操作できること。
- 既存Good Form、履歴、評価、Calibrationが更新前と同じであること。
- VoiceOverと文字サイズ拡大で短い状態と操作を確認できること。大きい文字サイズ・非常に低い画面ではスクロールが必要になる場合があります。
