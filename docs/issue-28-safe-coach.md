# v0.21.3 練習の事前通知と安全終了

カメラ開始→練習開始。カメラの近くに「残り目安：動画／姿勢・分析」が出ます。時間は容量・録画速度からの**推定**です。動画OFFでも姿勢記録・分析時間の監視は続きます。詳しい数値は「保存の詳細」に折りたたみます。

容量・時間・処理低下が近づくと、日本語／英語の音声と画面で予告し、通常5秒後に自動終了します。危険な残量・保存失敗・推論エラー・分析停止はすぐに終了処理へ進みます。音声OFF・音量0・音声非対応／Safariの再生拒否でも画面で知らせます。終了通知は通常の助言を停止した後に読み上げます。

終了中は最後の動画分割・姿勢チャンク・検出済みの分析待ちシュートを保存し、その後レポートを表示します。「自動終了」の理由は履歴にも残ります。自動終了後はカメラを停止します。再開時はカメラ開始から操作してください。手動の練習終了では従来どおりカメラを維持します。

## 判定と保存余裕

- 動画は既存の全一時動画＋新規確定分＋保存待ち＋現在の受信データ＋未受信分の推定を含め、合計128MiBに対して80％で予告、85％で即終了します。録画速度から2分割（30秒）分、最低8MiBの余裕を設け、これを割る場合も即終了します。推定録画速度は直近チャンクの移動平均で、1.5Mbpsの設定値に余裕を加えた234,375B/秒以上を使います。
- 姿勢記録は既存セッション＋確定／書き込み中／未保存フレームを合計し、32MiBの80％で予告・85％で即終了します。未保存フレームを残して最後にフラッシュします。最大20fps、保存形式は従来のままです。
- 1回60分に対し残り60秒で予告、残り10秒以下なら即終了します。通常は59分5秒付近で終了します。
- `storage.estimate()`が利用可能なら約5秒ごとに保存先の空き容量を取得し、未保存分・動画2分割・姿勢余裕・結果用8MiBを確保します。利用できなければ「不明」。端末のメモリ残量とは別で、推測しません。
- 実際の推論時間と結果の間隔を移動平均で観測。200ms超相当（約5fps未満）の状態が15秒続いた場合、または動画の保存待ちが15秒続いた場合は予告。分析結果が15秒途切れた場合は即終了します。人物が映っていないこと自体を処理停止とは扱いません。処理限界は観測に基づく推定です。
- 保存・推論・シュート分析のエラーでは即終了し、可能な記録を保持します。不完全な姿勢記録は従来どおり検出改善の評価に使いません。

IndexedDB v4・過去動画・Good Form・レビュー・Calibration・分析・履歴を移行／削除／初期化しません。終了理由などの任意フィールドを追加するだけです。不要な保存データの整理は従来どおり本人が選んで行います。サイトデータ削除は不要です。

## 限界とiPhone Safari確認手順

事前終了は保存余裕を増やしますが、突然の巨大チャンク、他画面からの同時保存、OSによるタブ強制終了、ストレージ見積りの変動、IndexedDB・MediaRecorderの停止処理が応答しない場合まで保存を保証できません。書き込み失敗時には過去データを削除せず、不完全表示と保存できた結果を残します。推論が応答しない場合も結果保存をカメラの終了待ちで止めない構造です。

実機iPhone Safariは未検証です。合成カメラ・短縮時間設定・保存失敗を使ったChromiumテストで検証しました。テスト用の短縮設定は通常のアプリ画面にはありません。

実機では次を確認してください。

1. 音声テスト後、日本語／英語、音声OFFで練習を開始。残り目安が縦横画面で読めること。
2. 容量が多い状態で、予告→自動終了→終了理由→レポートの順序を確認。最後のシュートと動画の末尾を再生すること。
3. 録画OFFでも残り分析時間が表示されること。停止ボタンを連打して二重保存がないこと。
4. 画面を離れる／ロックすると終了し、戻ったら保存された範囲を確認できること。背景での音声はiOSが制限する可能性があります。
5. 履歴・Good Form・既存レビュー・AI改善設定が残ること。Safariアドレスバー・Safe Area・音量・VoiceOver・低電力／発熱時の挙動を確認すること。
