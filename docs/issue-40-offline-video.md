# 保存した動画の読み込み・再解析（v0.23.0 / Issue #40 P0-1b）

練習日に撮影に集中し、後日同じ動画で検出を確認するための機能です。
ライブ撮影、従来の一括分析、Good Form、Shot Review、Personal Calibrationはそのまま残します。
この機能のレビューはライブの判定設定やCalibrationに自動反映しません。

## iPhoneで使う

1. 写真／ファイルアプリに原本を残します。Safariの「…」→ **動画を読み込んで再解析** を開きます。
2. **写真・ファイルから動画を選ぶ**。10分以内。元動画を先にローカル保存し、保存した内容をSHA-256で読み戻し照合します。照合済みの表示を待ってください。iCloud上だけにある動画は先に写真アプリでダウンロードしてください。
3. シュートする手・撮影角度・種別を選び、**動画から骨格を読み取る**。標準は毎秒15枚、詳細は毎秒30枚です。画面を開いたまま待ちます。進捗と中断ボタンがあります。MediaPipe Pose Liteを使い、動画や骨格を外部へ送信しません（初回はアプリのモデル配信ファイルを読み込みます）。
4. **骨格を使って再解析**。自動候補の本数・動画の位置・参考フォーム評価が表示されます。Good Formがなくても検出・手動登録は可能で、フォーム一致度は未算出です。
5. 動画を再生／シークし、**ボールが手を離れる瞬間**で **ここがリリース · 追加** を押します。ディップ開始ではありません。0本検出でも追加可能です。前後3秒移動・先頭への移動も使えます。
6. 登録した位置を選び、必要なら動画を合わせて **選んだシュートをここへ修正**。成否、フォーム評価の正誤、メモも保存できます。誤登録は **この登録を取り消す**。自動候補は **正解に登録／誤検出** を選びます。同じ位置に正解を重複登録しないため、0.5秒未満の近接登録は止めます。
7. 各操作後 **ローカル保存・読み戻し確認済み** を確認します。保存中・未保存・保存失敗を区別します。未保存のメモは保存してから他の操作に進んでください。
8. 動画を最後まで確認し、見逃し・誤検出を直した後、**動画の最後まで確認し…** にチェックします。**変更前後を比較** で現在とPR #39前のルールを、同じ骨格と正解で比較します。手動修正を加えると全編確認のチェックは解除され、比較の更新が必要です。
9. **正解・骨格・解析結果をJSONで書き出す**。準備完了後の **JSONを保存** をタップし、ファイルアプリで保存を確認します。JSONに動画は含みません。JSONと同じ元動画を一緒に保管してください。

再訪時は「読み込み済みの動画」から選びます。同じファイルを再選択してもSHA-256で同一原本と照合し、元動画を増やしません。「骨格を使って再解析」は既存の骨格を使うため動画の推論をやり直しません。「動画から骨格を読み取る」は明示的な取り直しで新しい骨格記録を作ります。過去の解析結果・手動修正は消しません。

元動画だけ不要になった場合、説明内の **この元動画だけを端末から削除** を使えます。確認後、その読み込み動画のBlobだけを外し、骨格・フォーム評価・自動判定・手動修正は保持します。元動画がなくても骨格から再解析できます。同一の原本ファイルを選び直すと復元できます。別の圧縮版は別動画として扱います。従来のライブラリ動画の削除動作は変更しません。

## どの数字か

- **自動候補**：選択中の自動解析が出した本数。正解とは未確定。
- **手動追加**：現在有効な正解のうち、手動で追加した本数。
- **誤検出として除外**：選択中の自動解析で誤検出ラベルを付けた候補本数。
- **確認した正解**：自動候補を正解として登録したもの＋手動追加の最終有効状態。取り消しは含めず、操作履歴を単純加算しません。
- **フォーム一致度**：Good Formとの計測差です。AIの正答率ではありません。自動位置からの評価は推定時刻による参考値であり、信頼度Lowを確実な評価とは表示しません。この画面では音声助言を追加しません。
- **精度比較**：正解と自動検出の±0.5秒、1対1対応による一致／見逃し／誤検出。重複検出は余剰分を誤検出とします。誤検出として除外した候補も、元の自動判定の採点では誤検出として数えます。人が直してからAIの元の結果を良く見せることはしません。Precision、Recall、F1の分母が0なら「—」です。成功／失敗の正答率ではありません。手動成否は保存しますが、自動成否判定はしません。

HomeCourtのカウンターや軌道描画は他アプリの推定表示です。正解として自動採用せず、人がリリース位置を確認します。OCR・軌道読取り・新しいボールAIは未実装です。

## 互換性と構造

IndexedDB `sports-form-lab` をv4→v5へ**追加のみ**で更新します。旧7ストア・旧レコードを書き換え／削除しません。

|新しいストア|内容|
|---|---|
|`offlineAssets`|SHA-256で一意な元動画、動画内時間の長さ、縦横寸法、原本のサイズ・形式・作成日時。Blobは必要時だけ読む|
|`offlineCaches`|モデル・オプション・入力640px・15/30fps・動画ハッシュ・座標形式を含むキー、完了／未完了、読み取った本数・時刻精度・欠損間隔|
|`offlineChunks`|120フレーム単位。時刻（動画開始から秒）＋33点×xyz・visibility、Float32、1フレーム133要素。旧ライブの14点45要素とは混在しない|
|`offlineRuns`|追記のみの自動判定。アルゴリズム版・パラメータ・手・アプリ版・骨格ID・Good Formの比較時点情報・元のフォーム評価|
|`offlineAnnotations`|動画IDに紐づく安定ID、最終有効な正解位置、成否、評価の正誤、メモ、取り消し、変更履歴、競合検知用の版|

元動画と正解は解析runの連番から独立しています。異なる解析結果を選んでも人間の正解は失われません。自動判定と人間の修正を上書き混在させません。人間の保存はトランザクション完了後に全レコードを読み戻して照合します。別画面で修正が先に保存されていれば競合として止めます。

ライブの検出、音声、フォーム採点ルール、Calibrationの適用値は変更しません。`auto-phases.js`と`session.js`には同じ計算をコンパクトな動作行から呼べる入口を加えます。従来の呼出しもこの入口を使い、既存テストで同じ結果を確認します。骨格全体のオブジェクト展開を避け、検出はWorkerで実行します。フォーム評価は候補前後の骨格だけ読みます。

## データ書き出しとCodex／Macでの反復検証

`psfl.offline-training` / `schemaVersion: 1` の標準JSONです。

- `asset`：元動画のID、SHA-256、長さ・寸法・日時・アプリ版。動画バイナリなし。
- `cache`：モデル・入力条件、実際に処理した標本数・時刻情報、骨格ID。
- `poseChunks[]`：`index`、`frames[]`。各フレームは`time`（秒）、`landmarks`（33点の`x,y,z,visibility`、推定不能はnull）。3D推定zは実寸ではありません。
- `runs[]`：元の自動検出とその評価、検出ルール版、パラメータ、比較時の基準情報。
- `annotations`：人間が確認した最終有効データと変更履歴。`origin`と`sourceRunId/sourceShotId`で自動由来／手動追加を区別。フォーム正誤の保存時には、表示した評価の`formReviewSnapshot`も分けて保持します（未算出ならnullで、学習根拠にしません）。
- `benchmark`：全編確認が済んでいるときの保存済みrunの照合結果（異なる手の設定は混ぜない）。

動画位置はすべて動画開始からの秒で、ブラウザの処理時間とは分離します。Swiftでも標準JSONデコーダで読める構造です。旧ライブ用の`shot-training`書き出しと区別します。

```sh
node scripts/verify-offline-video.mjs /private/path/shot-offline-xxx.json
```

JSONの版・動画／骨格の対応・全編確認・順序・骨格本数を検証し、保存された同じPose・最終正解で現在とPR #39前を再実行します。生動画を毎回推論する必要はありません。通常は最新runの手の設定を使用します。検出は既定パラメータのPose-only Sessionルールで、ライブの人物存在チェックや実時間の追跡落ちは再現しません。現行版は`session-pose-1.2`、比較版はコミット`92cfe6b`のSession判定（`session-pose-1.1@92cfe6b`）。PR #39前との差である持続条件を履歴比較専用に凍結しています。比較版をライブに適用する操作はありません。

同じデータで繰り返す自動テストはできますが、単一動画で調整して同じ動画だけで測った結果は一般的な改善の証明ではありません。アルゴリズム改善時には別のセッションを検証用に分けます。ユーザーの動画・生の骨格・出力JSONはリポジトリへコミットしません。

## 保存とバックアップの制限

- 保存先はSafariのこのサイトのIndexedDB。ブラウザ容量表示は端末の空き容量の保証ではありません。OSによる退避・サイトデータ削除に備えて、写真／ファイルの原本は別に残します。
- Google Driveへの**読み込み動画の直接バックアップはP1で未統合**。今回の画面はDrive保存済みとは表示しません。JSONと原本動画をファイルアプリ等から手動でバックアップできます。既存Live Coach用のDrive機能は変更しません。
- バックグラウンド処理、タブ強制終了からMediaPipe状態を厳密に途中復帰する機能はありません。未完了の骨格は検出・精度比較には使用しません。原本と以前の成功run、手動修正は残ります。
- 動画再生はSafariがデコードできる形式に依存。H.264 MP4/MOVを推奨。元動画全体をBase64やRGBA配列へ展開せず逐次シーク・推論します。
- 15/30fpsは標本を取得する間隔であり、元動画の全フレーム取得の保証ではありません。rVFCの表示時刻を優先し、古い表示フレームが返る場合はシーク位置による近似と記録。間隔・重複・実際の本数を記録し、精度の根拠を隠しません。
- ボール追跡はこの比較では無効。他アプリの軌道の色を本物のボールとして利用しません。複数人物ではMediaPipeの追跡先が変わる可能性があり、確認が必要です。
- 自動検出アルゴリズム自体の精度改善、旧Live Coachレビューへの全体的read-back導入、動画管理の全体刷新、Drive統合は別段階です。

## テストの再現

単体・ビルド：`npm test`、`npm run build`。
ブラウザテストにはPlaywrightとChromiumが必要です。人工の14秒縦動画を作ります（個人動画は使いません）。

```sh
ffmpeg -f lavfi -i color=c=0x123456:s=320x568:r=15:d=14 \
  -vf 'drawbox=x=140:y=110:w=35:h=300:color=white:t=fill' \
  -c:v libx264 -pix_fmt yuv420p /tmp/offline-fixture.mp4
npm run dev -- --port 5173
# 別の端末で
OFFLINE_VIDEO_FIXTURE=/tmp/offline-fixture.mp4 node scripts/check-offline-video.mjs
```

ネイティブ動画デコード・シーク・IndexedDBは実処理、Poseのみ人工推論を使います。v4既存データ保持、10連続登録、除外／修正／成否・評価・メモ、再読み込み、原本重複防止、骨格キャッシュ、推論なし再解析、指標とJSONのNode再検証、中断／失敗／同時編集、元動画のみ削除後の再解析、320〜430px縦／844px横を確認します。認識率の実データ試験とは区別してください。

## 実機iPhone Safariの最小確認

1. テスト用の公開前環境で、既存Good Form・動画・レビュー・Calibrationが残っていることを確認。
2. 写真／ファイルからHomeCourt圧縮動画を選択し、元動画保存・内容照合完了を待つ。0秒から再生し、±3秒、シーク、縦横切り替え、全身と骨格の重なりを確認。
3. 標準15fpsで骨格を最後まで読み取る。途中で中断し、再開操作で最初から取り直せることも確認。別タブに移動した場合は未完了の扱いと保存済みデータが残ることを確認。
4. 0検出でも手動10本を続けて追加。位置を修正、1本取り消し、成否・評価・メモを保存し、毎回読み戻し確認済み表示を確認。
5. 全編確認→比較。再解析やSafari再読み込みで手動正解が残ること、比較の本数が最終正解に一致することを確認。
6. JSONを書き出し、MacのCLIで同じ指標を確認。原本は別に保持し、必要ならテスト用元動画Blobだけを削除。フォーム評価・正解・骨格からの再解析が残ることを確認。
7. 従来のLive Coachで練習開始→音声確認→終了→保存→振り返り、従来のDrive保存、Good Form・クイック／全編チェックが動くことを確認。

実機iPhone Safariの速度・メモリ・長時間安定性、iCloudからの選択、ファイルアプリへの保存はクラウドのChromium試験では保証できません。

## 今回の検証結果

- 単体テスト229件、ビルド、新規ブラウザ試験、既存の練習開始・音声・録画フォールバック・安全停止・追跡復帰・クイック／全編・Shot Review・Driveの回帰試験が成功。
- 提供されたHomeCourt圧縮動画（144.685秒、約23MB）の読み込み→元動画保存→実際のMediaPipe Poseによる全編の標本抽出→現在／過去の再解析→JSON書き出しが完了。15fps設定で2,172枚、骨格あり2,126枚、19チャンク。ソースの全フレーム取得を意味しません。
- 検出候補は現行7本／PR #39前8本。成否や正しく認識した本数ではありません。全編の正解リリース位置はまだ確定していないため、実動画のPrecision／Recall／F1は未算出です。未確認の状態では指標計算が止まることも確認しました。
- 出力したJSONを最終コードで読み込み、元の動画推論なしで両ルールを再実行し、候補の区間・本数がブラウザ保存時と一致しました。
- クラウドのソフトウェアGPUで一連の処理に約19分30秒。iPhoneの性能測定値ではありません。実機の所要時間、発熱、メモリ、バックグラウンド・ファイル保存は未検証です。87MB原本の実処理も未確認です。
- 個人動画・生のPose・書き出しJSONはリポジトリに含めていません。
