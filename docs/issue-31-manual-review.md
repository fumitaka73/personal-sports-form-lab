# v0.21.4 シュート検出チェック

「シュートの確認」→練習を選ぶ→「シュート検出チェック」。

## 迷わず登録する

クイックは候補・検出の確認と手動登録、全編は詳細時間軸を使った確認です。どちらでも登録できます。

1. 再生位置バーや「−10秒／＋10秒」でシュートした位置へ移動。「再生／一時停止」で映像と骨格を確認します。
2. 「この位置をシュートとして登録」を1タップ。再生を一時停止して、その位置を保存します。
3. 「保存中…」→「保存しました：動画内の位置・保存時刻・確認済みシュート数」を確認。登録後は選択状態を残さず、続けて動画を進めて登録できます。
4. 既存の記号を選んでいても登録ボタンを使えます。ただし0.7秒以内にシュート・候補がある場合は、重複として理由を表示します。その候補を「シュート／正しい」と確認するか、位置修正を使ってください。

保存失敗では成功を表示せず、位置と元データを維持します。再読み込みでは保存済みの件数・更新時刻を表示します。確認済みシュート数は本人によるyesラベルの数で、シュート成功率やAI正答率ではありません。

モード切り替えは一時停止して、現在の位置を保ちます。新たに画面を開いたときの全編チェックは、未操作なら前回の確認位置から再開します。保存中・映像読み込み中・切り替え中は重複操作を防ぎます。

判定は選択中の1件に対して行います。「確認済み・候補の一覧」、数値による位置指定、位置の微調整・修正、やり直し、フィルタなどは折りたたみました。機能は残っています。動画なしの場合は説明し、「動画根拠なし」で追加するか本人に確認します。

動画の縦横比に合わせて表示枠を収めます。全身をクロップせず、映像と骨格に同じ座標変換を使います。横画面は映像・時間軸と登録・保存表示を左右に配置します。

## 検証データを書き出す

「保存・書き出し・確認の仕組み」→「手動登録＋姿勢の検証データを書き出す」→生成された保存リンク。動画本体や個人データを自動送信しません。関節座標・練習時刻・条件を含む個人の練習データなので、共有先を確認してください。

形式は外側の既存 `detection-check-1` を維持し、`training.schema = shot-detection-dataset-1` を追加します。

- `session`：元のライブ検出、モデル・取得版・検出器版・撮影条件・承認済み検出パラメータ。未保存の版はnullで、推測しません。
- `review`：元検出と修正履歴、yes／no／later／未確認、確認済み区間。
- `videoReferences` / `poseReference`：録画区間、Poseの保存状態・元の時刻範囲。動画のBlobは含みません。
- `training.windows`：元検出・候補・手動登録を含む正例／負例／未確認、動画内位置、前後2.5秒の参照範囲。未確認を正解にしません。
- `training.poseFrames`：時刻（元の単調増加時計・秒）、画面比率、14関節の `[id, x, y, visibility]`。画像上の正規化座標・鏡像なし。visibilityは可視性で、シュート確率ではありません。人物不在はlandmarks:null。
- 参照範囲のPoseを時系列で出力。登録なしなら先頭のPoseを出力。最大12,000フレーム。除外フレーム数・打ち切り・連続区間・元Poseの不完全状態を明示します。空白区間はつなぎません。`complete` は元Poseが完全で、全フレームを出せた場合のみtrueです。局所ラベルが全シュートの正解一覧だという意味ではありません。

読み込み・再生方法：

```sh
node scripts/verify-shot-training.mjs shot-training-SESSION_ID.json
```

`readTraining()`でJSONを検証し、33関節配列へ復元します。コマンドは現在の検出器のオフライン再生、候補探索、元ライブ検出の時刻と件数、本人のラベルを出力します。データや閾値を変更せず、自動学習しません。実際にブラウザでダウンロードしたJSONをこの読み込み処理と候補探索に渡し、元Poseと同じ探索結果になることをテストしています。

限界：保存Poseは2Dの14関節です。未保存のWorld座標やライブの追跡復帰状態、カメラ取得・推論タイミングを完全には再現できません。欠損・部分書き出し・未確認があるため、全練習のRecallやAI正答率を計算しません。候補探索とライブ検出は別ルールで、違いを照合する材料として使えます。原因の断定や閾値緩和は別途実データによる検証が必要です。

## iPhone Safari実機の確認

実機は未検証です。Chromiumのタッチ・320/390/430px縦／横画面と合成動画・Poseで検証しました。

- 再生・シーク・連続追加、選択中の追加、重複メッセージ、保存表示、再読み込み。
- クイック⇄全編を繰り返し、同じ位置・ラベル・確認済み区間を保持すること。
- 縦横動画で全身と骨格が切れず、保存表示と登録ボタンがナビ・Safe Area・Safariアドレスバーに隠れないこと。
- 動画なし、欠損区間、低容量、VoiceOver、文字拡大、JSON／動画の保存リンク。
- Good Form、動画、Pose、Calibration、既存レビュー・元分析・履歴が残ること。サイトデータ削除は不要です。
